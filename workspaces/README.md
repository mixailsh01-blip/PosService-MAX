# Пространства и обучение СПРТ

## Согласованная схема

| Пространство | Сотрудник | Администратор обучения |
|---|---|---|
| Библиотека СПРТ | VIEWER: читает и запускает общие запросы | OWNER: поддерживает эталонные коллекции |
| Рабочее · сотрудник | OWNER своего пространства | Без автоматического доступа к чужим рабочим пространствам |
| Обучение · сотрудник | EDITOR своего пространства | OWNER всех учебных пространств |

Для библиотеки выбирайте **Мои окружения → iiko Cloud API** в селекторе
окружений. Общие запросы можно выполнять с личными переменными. В библиотеку
не загружаются клиентские ключи и окружения. При первом создании личного
окружения переносятся переменные из прежнего рабочего пространства сотрудника;
если личное окружение уже существует, оно сохраняется без изменений.

`Моё пространство` — встроенное пространство Hoppscotch; оно остаётся доступным.
Старые рабочие пространства и их коллекции сохраняются с прежними названиями.
Эталонная коллекция загружается в библиотеку один раз, затем изменения
ответственного видны всем. Повторная сверка не заменяет его правки.

## Автоматизация

Сервис проверяет зарегистрированных пользователей каждые 30 секунд и при старте.
Пользователь должен сначала войти в Hoppscotch. Все изменения пространств и
членств выполняются одной транзакцией под PostgreSQL advisory lock.
Рабочее пространство доступно только своему сотруднику, учебное — сотруднику
и указанным администраторам. Посторонние членства в этих управляемых
пространствах удаляются при сверке. Остальные команды не изменяются.

Учётка администратора задаётся `SPRT_TRAINING_ADMINS` (по умолчанию
`m.demetiev@sprt-service.ru`, как в проверенной базе). Если ни один
администратор ещё не зарегистрирован, сервис прекращает запуск без изменения
членств. Права `isAdmin` Hoppscotch сами по себе не открывают отчёт.

## Прогресс обучения

`/sprt/training` показывает сводку и подробности по каждому сотруднику:
задания, номер попытки, количество учебных запросов, даты и историю событий.
Доступ проверяется сервером по действующей сессии Hoppscotch и точному email
из базы; email/uid из тела запроса для авторизации не используются.

Сохраняются только результаты тренажёра. Тела запросов, токены, заголовки и
клиентские секреты в события не записываются. Повторная доставка UUID-события
не дублирует результат, сброс увеличивает попытку и сохраняет историю.
Прогресс из `UserSettings.SPRT_LEARN` импортируется один раз; старые даты
помечаются неизвестными. Сброс не восстанавливается из старого прогресса.

Это учёт выполнения браузерного тренажёра, а не защищённый экзамен: факт
успеха сообщает клиентский симулятор. Backend проверяет сессию, порядок
заданий, номер попытки и формат событий, но не исполняет учебные запросы.

## Установка на проверенный сервер

Нужны работающие `hoppscotch-hoppscotch-1`, `n8n-postgres`, Docker Compose
с поддержкой `env_file.format: raw`, Python 3 и доступ к Docker registry/npm.

Из корня распакованного пакета:

```bash
sudo bash deploy/install-workspaces.sh
```

Установщик делает root-only резервную копию базы, собирает отдельный образ
Node/pg, наследует сети и HTTPS-настройки Traefik, затем подключает новые
статические файлы тренажёра. Полная пересборка Hoppscotch не требуется.
Секрет DATABASE_URL берётся из текущего контейнера и хранится в root-only
env-файле; в вывод не попадает. Патч авторизации сохраняется: установщик
берёт полный список Compose-файлов из меток существующего контейнера.

После установки управление основным приложением выполняйте через:

```bash
sudo bash /opt/sprt-workspaces/app-compose.sh ps
sudo bash /opt/sprt-workspaces/app-compose.sh up -d --no-deps hoppscotch
```

Старый `deploy/private-teams.sql` и watcher `local/private-teams.sh` больше
не запускать: прежние правила не соответствуют новой схеме. Существующий
watcher/cron со старым скриптом нужно остановить до установки.

Проверка после установки:

1. Под администратором открыть `/sprt/training`: должны быть все сотрудники.
2. Под сотрудником обновить страницу: библиотека, своё рабочее и своё обучение.
3. Убедиться, что чужое обучение отсутствует, а `/sprt/report` возвращает 403.
4. Выполнить учебное задание: прогресс появляется в отчёте администратора.
5. Перезагрузить страницу: прогресс сохраняется; старые ключи и запросы на месте.

## Откат интерфейса/сервиса

```bash
sudo bash /opt/sprt-workspaces/current/previous-app-compose.sh up -d --no-deps --pull never hoppscotch
sudo docker compose -f /opt/sprt-workspaces/current/compose.json down
```

Откат отключает новый интерфейс и автоматизацию. Добавленные пространства,
результаты и изменённые членства остаются в базе. Полный возврат базы из
`/opt/sprt-workspaces/backups/` — отдельная операция, которая заменяет данные
на момент резервного копирования. Не восстанавливать её поверх новых
пользовательских изменений без проверки.

## Обновление существующей установки из Git

После публикации ветки в репозитории:

```bash
cd ~/apps/PosService-MAX
git pull --ff-only
sudo bash deploy/update-workspaces.sh
```

Скрипт создаёт новый release и резервную копию, строит образ из текущего
checkout, сохраняет настройки сетей и HTTPS и подключает обновлённый тренажёр.
Ручные копии исходников в `/opt` не требуются. Предыдущая версия остаётся
доступной; команда отката выводится в конце установки.

Версия `2026.11.18.2` исправляет потерю браузерного прогресса при миграции:
сначала сохраняется локальная копия, затем старые флаги объединяются с
серверными. Пустой серверный прогресс больше не заменяет локальный без
попытки переноса. Явный сброс курса блокирует восстановление старых флагов.
Если первая версия уже затёрла локальный кеш, обновление читает **только
флаги обучения** из первой резервной копии перед установкой. Отсутствующий
в сохранённых источниках результат не угадывается и не выставляется вручную.

`/sprt/settings` — настройки диагностики: собственный прогресс, версия,
статусы запросов и экспорт JSON. В тренажёре есть ссылка «Настройки и
диагностика»; ссылка из основной страницы настроек появится при следующей
полной сборке Hoppscotch. Браузерный журнал включается пользователем,
сервер хранит в памяти последние 200 записей только с безопасными полями.
Администратор может диагностировать обучение коллег, остальные — только своё.
Заголовки, тела запросов, cookie, пароли и клиентские ключи не экспортируются.

## Проверки разработчика

```bash
cd workspaces
npm ci
npm test
```

Тесты исполняют PostgreSQL-запросы в PGlite: создание и повторная сверка,
сохранность старых данных, права, импорт прогресса, последовательность,
дедупликация событий, сброс и HTTP-авторизация. Advisory lock проверяется
только на уровне наличия вызова: PGlite-тесты используют одну сессию.
Docker-образ и HTTPS-маршрут нужно проверить при установке на сервере.
